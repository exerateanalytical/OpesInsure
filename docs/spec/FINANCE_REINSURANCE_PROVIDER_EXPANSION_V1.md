# OpesInsure Finance, Reinsurance & Provider-Network Expansion v1.0 — owner specification (2026-09-24)

Full 111-section text supplied by the owner in session 2026-09-24. Extends the working register (not separate systems). **Register now 670 screens** (572 + 98).

## Governing rule
One governed transaction chain, never separate financial truths: Insurance domain event → Financial obligation → Payment/settlement → Reconciliation → Accounting → Reporting. Customer → Quote → Policy → Premium → Payment → Commission/carrier share → Claims → Provider/adjuster/repairer → Settlement → Accounting → Regulatory reporting. Financial status is event-driven (e.g. ClaimPaymentCompleted → settlement updated → payable closed → journal posted → party notified); any claims/finance mismatch is an explicit reconciliation exception.

## Part I — Insurance finance & technical accounting (FIN-X-001…034, +34)
Transaction → obligation → payment → accounting entry. Financial parties: customer, policyholder, broker, agent, insurer, reinsurer, co-insurer, medical provider, garage, adjuster, supplier, bank, mobile money provider, tax authority. Premium components BASE_PREMIUM, COVERAGE_PREMIUM, RISK_LOADING, DISCOUNT, NET_PREMIUM, TAX, LEVY, STAMP_DUTY, SERVICE_FEE, OTHER_CHARGE, GROSS_PREMIUM with snapshots. Premium status NOT_DUE, DUE, PARTIALLY_PAID, PAID, OVERPAID, OVERDUE, CANCELLED, REFUNDED, PARTIALLY_REFUNDED, WRITTEN_OFF (separate from payment status). Receivables (debtor, source, amount, currency, due, outstanding, aging, status) and payables; instalment schedules; customer/broker/carrier/agent accounts (never from latest payment only); commission lifecycle SALE → CALCULATED → ACCRUED → EARNED → APPROVED → PAYABLE → PAID (REVERSED, CLAWED_BACK, ADJUSTED, DISPUTED); refund engine; cashier sessions (opening, collections, refunds, transfers, closing count, variance, supervisor approval; no anonymous cash); mobile-money clearing (provider success ≠ bank settlement); bank reconciliation (MATCHED, PARTIAL, UNMATCHED, DUPLICATE, OVERPAYMENT, UNDERPAYMENT); suspense account (research → match → reclassify, no deletion); carrier settlement lines; provider settlement; claim financials (estimate, reserves, indemnity, deductible, prior payments, recoveries incl. reinsurance, net cost); event-based reserve ledger; technical categories (written/earned/unearned premium, claims incurred/paid/outstanding, commissions, reinsurance premium/recovery) mapped via insurer configuration; UPR, IBNR/IBNER/outstanding/mathematical reserves stored/imported/interfaced — no invented actuarial methods; life technical values from insurer actuarial engines; stable business events mapped to tenant GL; journal engine (debit = credit; DRAFT → VALIDATED → APPROVED → POSTED → REVERSED; corrections by reversal); period close with privileged reopening; aging CURRENT/1–30/31–60/61–90/90+; finance exception centre; 20 finance reports.

## Part II — Reinsurance (REI-001…026, +26)
Policy/risk → gross exposure → retention → ceded portion → treaty/facultative → reinsurance premium → claim → recovery. Parties CEDANT, REINSURER, REINSURANCE_BROKER, RETROCESSIONAIRE; reinsurer master; TREATY / FACULTATIVE / FACULTATIVE_OBLIGATORY; QUOTA_SHARE, SURPLUS, EXCESS_OF_LOSS (layers, attachment, exhaustion), STOP_LOSS; effective-dated treaty versions; facultative placement (slip, participants, signed share validation); gross/net exposure; ceded premium, commission, brokerage, taxes; premium/claim/risk bordereaux; recovery statuses ESTIMATED … CLOSED; large-loss notification thresholds; reinstatement premium; cedant↔reinsurer settlement; reinsurance accounting events; exposure dashboard.

## Part III — Co-insurance (COI-001…008, +8)
Lead insurer (apériteur) + co-insurers, participation totalling 100% (unless configured), premium/claim/commission/reserve/settlement shares, configurable lead rights; never treated as reinsurance.

## Part IV–V — Health provider network & portal (PRV-001…030, +30)
Insurer → network → canonical provider → facility → specialty → service → contracted tariff (never duplicated per insurer). Credentialing PROSPECT → APPLICATION → UNDER_REVIEW → APPROVED → ACTIVE → SUSPENDED → TERMINATED. Insurer-named networks; membership with effective dates; contracts; medical service catalogue with provider code mapping; versioned tariffs (price, contracted price, copay, insurer share). Eligibility → ELIGIBLE, ELIGIBLE_WITH_COPAY, PREAUTHORIZATION_REQUIRED, OUT_OF_NETWORK, COVER_NOT_ACTIVE, BENEFIT_EXHAUSTED, REVIEW_REQUIRED. Digital health card (minimum QR data). Preauthorization with insurer-configured rules; guarantee of payment; admission, outpatient, pharmacy (formularies), laboratory workflows; provider claim validation; provider claim states DRAFT … DISPUTED; explanation of benefits (no internal medical/fraud notes); provider statements, payments, disputes, factual analytics; benefit accumulator (member/family/benefit/sub-benefit/policy); cashless, reimbursement or both on one benefit engine; out-of-network; anomaly indicators trigger review only. Provider roles PROVIDER_ADMIN, FRONT_DESK, DOCTOR, BILLING_OFFICER, PHARMACY_USER, LAB_USER, FINANCE_USER; simple portal flow.

## Part VI–VII — Controls and product integration
Idempotency on callbacks, refunds, settlements, commission/claim payments, recoveries, journal posting. Maker-checker on refunds, manual journals, claim payments, provider/carrier/reinsurance settlements, commission adjustments, reserve overrides, write-offs. Monetary audit (who, what, why, source, amount, currency, statuses, approval, time, external reference). Product versions reference premium, tax, commission, accounting, reserve, provider network, reinsurance and co-insurance rules; reinsurance by effective treaty version.
