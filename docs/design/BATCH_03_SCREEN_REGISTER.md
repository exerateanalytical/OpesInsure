# Batch 03 Screen Register

All screens inherit the established navy, ivory, blue, emerald, amber and red tokens. Monetary tables use tabular numerals and right alignment. Status always includes text and an icon. Dense financial data scrolls on narrow screens rather than shrinking, overlapping or distorting.

| Module | Screens | Lucide icons |
|---|---|---|
| Policy | Directory; policy detail; certificate summary; coverage; status timeline; issuance review | `ShieldCheck`, `FileBadge2`, `ListChecks`, `History`, `BadgeCheck` |
| Policy servicing | Renewal; endorsement request/review; cancellation; reinstatement; approval comparison | `RefreshCw`, `FilePenLine`, `Ban`, `RotateCcw`, `GitCompareArrows` |
| Payments | Payment request; MoMo authorization; processing; success/failure; receipt; refund request/approval; chargeback | `WalletCards`, `Smartphone`, `LoaderCircle`, `CircleCheckBig`, `CircleX`, `ReceiptText`, `Undo2`, `ShieldAlert` |
| Ledger | Chart of accounts; journal list/detail; manual adjustment; reversal; account activity | `BookOpenText`, `Rows3`, `Scale`, `RotateCcw`, `Activity` |
| Commission | Rule versions; accruals; vesting; partner balance; holdback; clawback; payout request | `BadgePercent`, `Clock3`, `Wallet`, `ShieldEllipsis`, `UndoDot`, `SendHorizontal` |

Refunds, manual journals, reversals and policy-service approvals use a review panel that shows requester, approver, reason, before/after values and audit correlation ID. Approval and destructive actions are never adjacent without separation and confirmation.
