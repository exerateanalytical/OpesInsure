## How detection works (and its limits)

- **Service method:** each controller method body is parsed; calls on constructor-injected, property-typed or
  parameter-typed classes under `Application\`, `Domain\` or `*Service` are recorded as `Class::method`.
  Cross-cutting helpers (`TenantContext`, `AuditWriter`, `OwnershipScope`, `PartyResolver`, `PartnerBook`,
  `PlatformSettings`) are ignored for matching, otherwise every page "covers" everything.
- **Filament:** covered if a file in `app/Filament` (plus `app/Livewire`) mentions the service's short class name and
  calls `->method(`. Controllers without a domain service fall back to: a Filament resource for the Eloquent model the
  controller touches, with a Create page (collection POST), Edit page/action (PUT/PATCH) or Delete action (DELETE).
- **Account portal:** path expressions in the Blade/JS (`'/claims/' + c.id + '/payments/' + p.id + '/paid'`) are
  rebuilt, variables become a wildcard that only matches a `{param}` route segment. A variable action suffix
  (`'/claims/' + c.id + path`) is therefore **not** counted: the claims desk may cover a few more claim actions than reported.
- **Classification** is path/permission based: `/webhooks`, callbacks, `inbound`, `integration.client` -> SYSTEM_ONLY;
  `/auth/mobile/*`, devices, push, attestation, crash reports, offline queue, `/mobile/uploads` -> MOBILE_ONLY_OK;
  customer paths (`/mobile/*`, `/me/*`, `/public/*`, customer-facing quotes/proposals/payments with no permission
  middleware) -> CUSTOMER_WEB_NEEDED; everything else (permission-gated, partner/carrier/broker/admin) -> STAFF_DESKTOP_NEEDED.
  A handful are borderline (for example `POST /quotes/{quote}/offers/{offer}/premium-overrides/{override}/apply` is
  CUSTOMER_WEB_NEEDED only because it has no permission middleware; it is a staff action).
