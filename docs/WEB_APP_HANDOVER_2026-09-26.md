# Web app handover (2026-09-26)

Live: https://insurance.opesdatacenter.tech, release **r20260926-191117** (commit 2ea5d75). Backend only; the mobile app is handed over separately.

## 1. Summary of the current state
The **back end, the data and the APIs** are largely built and deployed. The **web user interface is not.** Most of the work in Batches 1–17, the Gap Closure Pack and document security D1–D4 went into the domain services, database, API endpoints, seeders and tests (1,819 tests). The owner's assessment is correct: much of what the back end can do has **no web screen**, or only a basic list and form screen.

## 3. Known gaps in the web UI (owner-reported; partly confirmed by audit)
**Confirmed:** 59 of the 109 Filament resources have **no detail (view) page**. They are list and edit screens only. These include:
- Generated documents, certificate templates, document numbering and issuance profiles, physical security assets
- Claim decisions, claim reserves, approval requests, work queues
- Tariff versions, coverage and exclusion definitions, cancellation rules
- The whole master-data and vehicle-master family (values, reviews, merges, imports, overrides, makes/models/generations/variants)
- The CIMA register family, institution profiles and verification labels
- Memberships, invitations, devices, payment connections, sticker batches and inventory, risk assets

**Also missing or incomplete:**
- **Detail pages** with tabs (overview, documents, history/audit, related records) for policies, claims, quotes, documents, parties and partners. Where view pages exist, most are a flat field dump.
- **Flows exposed only through the API.** Examples: claim lifecycle actions, document template submit → approve → publish, endorsements, cancellations, provider pre-authorization, settlements, and reinsurance. These need buttons, modals, wizards and confirmation steps.
- **Configuration UI:** letterhead design (only an action exists: `Admin/Actions/LetterheadActions.php`), document template editor, seal/security asset upload with a preview, and tenant/branch settings pages.
- **Public site redesign (D1):** still waiting for the owner's design folder, which was never found on disk.
- **Provider portal:** the screens in the provider portal specification are only partly built.
- **Dashboards and reports:** mostly API only.

Honest estimate: the back end is roughly 80–90% built, but the web UI covers only a minority of it. The owner's figure of about 90% missing is plausible for detail pages, tabs, actions and configuration screens.

## 5. Proposed next phase: web UI build-out
Work in this order. Each batch is tested and deployed before the next starts.
1. **Core detail pages.** Policy, claim, quote/proposal, document, party/customer, broker/agent. Each gets tabs (overview, documents, payments, history/audit) and header action buttons wired to the existing services.
2. **Workflow actions.** Claims, endorsements/cancellations, template approval, and provider pre-authorization. Build them as Filament actions and wizards, using the permission checks the API already has.
3. **Detail pages for the 59 list-only resources.** Use one shared infolist pattern (never duplicate).
4. **Configuration screens.** Letterhead designer with a PDF preview, template editor, seal/security asset upload, tenant/branch settings.
5. **Provider portal, dashboards and reports.**
6. **Public site redesign**, once the design folder is provided.
