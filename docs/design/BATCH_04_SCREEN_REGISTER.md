# Batch 04 Screen Register

Batch 4 inherits the OpesInsure visual tokens and accessibility constraints. Reconciliation and settlement numbers use tabular figures. Evidence viewers prioritize the document itself and never place controls over evidence. Certificate verification is a neutral public surface and does not expose unnecessary personal data.

| Module | Screens | Lucide icons |
|---|---|---|
| Reconciliation | Import; processing; summary; matched rows; exception workbench; resolution; history | `FileInput`, `LoaderCircle`, `ChartNoAxesCombined`, `BadgeCheck`, `TriangleAlert`, `ListChecks`, `History` |
| Settlement | Batch list; builder; policy items; review; approval; instruction; acknowledgement | `Landmark`, `ListPlus`, `Rows3`, `ScanSearch`, `BadgeCheck`, `SendHorizontal`, `ReceiptText` |
| Claims | FNOL; claim detail; evidence checklist; timeline; assessment; carrier handoff; decision; dispute | `ClipboardPlus`, `ClipboardList`, `Files`, `History`, `ClipboardSearch`, `Send`, `Gavel`, `MessageSquareWarning` |
| Documents | Capture/upload; malware state; OCR review; verification; version history; access history; retention hold | `ScanLine`, `ShieldAlert`, `TextSearch`, `BadgeCheck`, `History`, `Eye`, `ArchiveRestore` |
| Certificates & stickers | Template versions; issue certificate; QR verification; certificate detail; void; stock; custody; assign | `PanelsTopLeft`, `FileBadge2`, `QrCode`, `ShieldCheck`, `Ban`, `PackageOpen`, `Route`, `Link2` |

Exception tables maintain fixed identifiers, money, status and action columns. Long raw-provider data opens in a drawer instead of widening or distorting the page. Mobile claim intake uses one task per step with persistent draft state.
