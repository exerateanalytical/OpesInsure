## Part III — RBAC & delegated authority
Permission naming module.resource.action; scopes OWN, TEAM, BRANCH, REGION, ORGANIZATION, TENANT, ASSIGNED, PRODUCT, PORTFOLIO; role profiles (customer, agent, broker producer/supervisor/administrator, underwriter, senior underwriter, claims officer/manager, finance officer/approver, compliance, provider user, reinsurance officer, system administrator — admin privilege ≠ business-data privilege). Authority check algorithm (permission → scope → active membership → product/branch authority → threshold → maker-checker → regulatory guard → valid transition); threshold exceeded → CREATE REFERRAL.

## Part IV — API architecture

Endpoint families as listed (§136–155) incl. POST /coverage/check. Webhooks with subscriptions, deliveries, retry and dead-letter (§156–157).

## Final engineering principle
One customer identity · one policy truth · one claim truth · one financial truth · one document history · one audit history — across many insurers, brokers, products, branches, providers, integrations and operating modes.

## Reconciliation notes with the current codebase (to be resolved through ADRs)
- Current tables use UUID primary keys (not bigint + public UUID) — ADR needed: keep UUID PKs or migrate.
- Money is stored as integer minor units (`*_minor`) — consistent with §175.
- Existing `app/Domain` folders are mostly empty; logic lives in `app/Application` services and controllers — migration toward the §173 structure is incremental.
- Change request ID format updated to CR-YYYY-NNNN in CHANGE_REQUEST_LOG.md.
